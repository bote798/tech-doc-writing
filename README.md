# tech-doc-writing

一个给 AI agent 用的技术文档写作 skill：命令为主、叙述为辅。

按文档类型定必填项，按固定适用项评分，附机械检查脚本。写部署手册、排障记录、README 时加载。

读完你能判断它是否适合当前任务，并完成安装。

## 为什么需要它

AI 写文档常有三类问题：

- 模板填空：六段都在，每段一句空话。
- 句长失控：一段顶一页，读者找不到动作。
- 命令不可复制：缺注释、缺预期、危险操作没有标注。

这个 skill 用固定骨架、句法阈值和评分表约束这三类问题。

## 安装

DSH 只扫描技能根目录下的一层：每个技能一个目录，目录里放 SKILL.md。推荐用目录联接，让仓库成为唯一事实源。

```powershell
# 目的：创建目录联接，改仓库立即生效
# 幂等：否（目标已存在时失败）
# 预期：输出 Junction created
cmd /c mklink /J "$env:USERPROFILE\.dsh\skills\tech-doc-writing" "<repo>\skills\tech-doc-writing"
```

`<repo>` 换成仓库 clone 路径。也可以复制安装：

```powershell
# 目的：复制一份，不跟随仓库更新
# 幂等：可重复（覆盖已有文件）
# 预期：技能目录出现 SKILL.md
Copy-Item -Recurse -Force "<repo>\skills\tech-doc-writing" "$env:USERPROFILE\.dsh\skills\"
```

装好后可用 `skill` 工具加载，或输入 `/tech-doc-writing` 显式调用。

## 快速开始

```text
输入：写一份 nginx 部署文档

输出（操作步骤六段）：
1 目标    一句话：做完得到什么
2 前提    系统/版本/权限/网络/备份
3 步骤    命令块 + 预期结果
4 验证    独立命令，输出可核对
5 回滚    反向操作，同样带注释
6 已知坑  表格：现象 → 原因 → 处理
```

审已有文档时用 `audit`：输出评分与问题清单，不改原文。

## 三种模式

| 模式 | 触发 | 输出 |
|---|---|---|
| `write` | 从零写 | 完整文档 + 自检 |
| `audit` | 审、评、打分 | 评分 + 问题清单，不改文 |
| `rewrite` | 改、润色、就地改 | 改写稿 + 改动说明 |

判定顺序固定：先看有没有现成文档。有且要意见选 `audit`，有且要改写选 `rewrite`，没有选 `write`。

## 评分

每类文档有固定的适用项与满分，逐项 0/1/2。

| 类型 | 满分 |
|---|---|
| 操作步骤 | 24 |
| 排障记录 | 18 |
| 事故复盘 | 10 |
| 交付说明 | 12 |
| 变更记录 | 12 |
| 参考页 | 10 |
| README | 10 |
| 教程 | 18 |
| 概念页 | 10 |

档位：

- ≥ 90%：可发布
- 75–89%：局部修改
- 60–74%：调整结构
- < 60%：建议重写

阻断项与分数无关，任一存在即不可发布：

- 事实错误，或关键事实无法核实
- 类型必填项缺失
- 步骤按文档做不完
- 关键信息只在截图里

评分第 0、5、6、7、8、10 项为 0，同样阻断。

## 编辑契约

改写现有文档时守六条：

1. 不改事实：数字、版本、条件、否定、确定性。
2. 受保护区域原样：代码、命令、路径、URL、标识符、引用。
3. 不编造：原文没有的数值、时限、因果不补。
4. 不越权：`audit` 不改文；`rewrite` 默认不动结构。
5. 不删警告与例外来缩短文档。
6. 改动要报：改了哪里、是否动结构、哪些待确认未解决。

## 机械检查

`scripts/lint_doc.py` 检查六类格式问题，不替代人工判断。

```bash
# 目的：检查一份文档的机械问题
# 预期：E 级为 0 时退出码 0
python scripts/lint_doc.py docs/deploy.md
```

检查项：行尾注释、多命令串联、占位符、命令块缺注释、危险漏标、数字区间写法。

个别合法写法用行级忽略：`# lint:ignore E1,E2`。


## 适用与不适用

| 适用 | 不适用 |
|---|---|
| 部署、升级、回滚手册 | 营销文案 |
| 排障记录、事故复盘 | 叙事文章 |
| 交付说明、变更记录 | 法律文本 |
| README、教程、概念页、参考页 | 代码与命令本身 |

## 测试与验证

- 主规范、README 与全部资产通过自带 lint：0 条 E 级、0 条 W 级。
- 12 组反例覆盖常见错误。
- 3 档评分锚点给判分样例。
- 14 条回归用例覆盖触发与能力。

## 限制

- lint 只查格式，不查语义。截断写、权限过宽、参数名错都查不出。
- 句法规则以中文为主。英文文档只守句长与术语一致。
- 评分需要证据。写不出证据的项按 0 分。
